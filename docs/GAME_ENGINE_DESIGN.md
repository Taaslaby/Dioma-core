# GAME ENGINE DESIGN — e-life движок dioma

> Версия: 0.1 (черновик)
> Дата: 2026-08-27
> Автор: Atlasov anton (при участии AutoCoder)
> Кодировка: UTF-8

Документ описывает целевой дизайн игрового движка dioma как **полноценной
игры в духе Creatures (1996)**: цифровая жизнь, которую можно смотреть,
учить, разводить и терять. Всё ниже привязано к фактическому состоянию кода
на момент написания (`cargo check --all-targets` — зелёный, 1 warning).

---

## 1. Видение и дизайн-принципы

**Одна фраза:** dioma — это живой мир, где существа — обучаемые спайковые
мозги на честном метаболизме, а игрок — садовник, а не программист.

Принципы, которые уже заложены в код и должны сохраняться:

| Принцип | Как выражен сейчас |
|---|---|
| Детерминизм | Рост и мутации выводятся из сидов (`XorShift`); мир детерминирован по сиду (`Arena::new(seed, map)`) |
| Слои зависят только вниз | ui → world → mind → body → engine → taas-checkmate; engine не знает ни о еде, ни о пикселях |
| Эмерджентность через обучение | дофаминовая пластичность, инстинкты `burn_into`, conditioning-механики |
| Эволюция меняет не только веса | гены правил «Пифия» (динамика клеток), тропическая перестройка, сон-консолидация |
| Врождённое ≠ выученное | геном наследуется, веса мозга — нет; выученное сворачивается в инстинкты (эффект Болдуина) |
| Всё наследственное — в `.taas` | формат снапшотов SNN уже есть в taas-checkmate |

**Не-цели:** не делаем 3D, не делаем экшн-геймплей, не делаем мультиплеер,
не делаем «игру-песочницу без правил» — нужен мир с последствиями
(голод, болезни, смерть, утрата).

## 2. Текущее состояние (инвентарь)

### 2.1 Слои и модули

| Слой | Модули | Статус |
|---|---|---|
| **engine** (ядро) | `genome` (Grown), `grow` (prometheus), `neurons` (Brain: LIF/HAAP, 3-факторная пластичность, гомеостаз), `rules` (Пифия), `graph` (тропическая перестройка), `instincts`, `behavior` (наследуемые IfAct-программы), `biocell`/`biovm` (клеточная ВМ со snapshot/restore), `pythia_vm`, `regulatory`, `gpu`, `perf`, `vm` | работает, проверено бинами |
| **body** | `organs` (HH-спина 10S/10I/10M + HAAP-средний мозг + LIF-кора), `metabolism` (кровь, стехиометрия, глюкоза), `physiology` (температура, Q10, архетипы), `cell_chemistry`, `tissue` | работает; tissue/cell_chemistry — свежие заготовки |
| **creature** | `Creature` (Sense→Brain→Action), `genome` (Steering + инстинкты + гены Пифии + гены метаболизма; σ=0.05/0.08/0.10/0.10) | работает: `new`, `from_genome`, `spawn_child`, `tick` |
| **env** | `map` (комнаты-Rect, двери с проницаемостью, CA веществ: тепло/влага/свет/питание), `math`, `id` | работает |
| **script** | CAOS-подобная ВМ: `lexer` → `compiler` → `machine`; `doif/else/endi`, `repn/repe`, `wait`, `stop`; `va0..99`, `vg0..99`; реестр команд + `Services`-трейт | работает; команд ~15 |
| **world** | `agent` (Cls{family,genus,species}, слоты ACTIVATE1/ACTIVATE2/DEACTIVATE/HIT/EAT/TIMER, сообщения), `sim` (World: команды, журнал, таймеры) | работает |
| **sim** | `Arena` (ягоды: рост, потомство, регенерация 150 тиков, потолок 24), `evolution` (поколения, отбор, Болдуин) | работает, но это **бенчмарк**, не игра |
| **mind** | `bridge.rs` (`CreatureMind`, мост в karmac `SpikingBrain`) | **мёртвый код**: `pub mod mind` не объявлен в lib.rs |

### 2.2 Ключевые константы (факты для проектирования)

- Мировой тик = **25 мс** (`TICK_MS`); мозг: LIF 50 подшагов/тик, HAAP 500 подшагов при dt=0.05
- Sense: `smell_l/r`, `wall_l/r`, `food_near`, `wall` → Action: `steer`, `drive`, `eat`
- Сон-консолидация: `memory_snapshot`/recall — механизм есть, в жизненный цикл не встроен
- Инстинкты прожигаются «первым сном» (`Instinct::burn_into`)
- Скриптовые команды: `posx posy nudge mvto fam gen near mesg kill out rand` и др.
- Бины: `dynasty`, `evolved-rules`, `skinner-box`, `conditioning`, `sardana-probe`, `grow-viz` — все исследовательские

### 2.3 Что отсутствует целиком

Рендер, ввод, звук, игровой цикл, свободный режим жизни, старение,
размножение в реальном времени, обучение игроком, save/load мира,
игровой контент (кроме ягод), UI. Подробности — в разделе 3.

## 3. Гэпы и целевые улучшения

### 3.1 Игровой цикл и «игровой» бинарь

**Проблема:** все 6 бинов — исследовательские. Игры нет.

**Цель:** бинарь `dioma` (или `observatory`), запускающий мир:

```
init (сид, карта, стартовые существа)
loop {
    input()          // мышь/клавиатура → команды игрока
    sim.step()       // ровно один мировой тик (детерминированный)
    view.render()    // интерполяция между прошлым и текущим состоянием
}
```

**Дизайн-решение — разделение Sim/View:**
- `Sim` = существующие `Arena`/`World` + жизненный цикл (3.5). **Никакого UI-кода** в sim-слое.
- `View` = отдельный модуль `ui/`: читает состояние sim через геттеры, рисует.
- Рендер с интерполяцией: хранить предыдущий `Critter.pos`, рисовать
  `lerp(prev, cur, alpha)` — иначе при 25 мс тике движение будет дёрганым.
- Тик фиксированный; рендер-кадр — свободный (vsync/60fps).

**Приёмка:** `cargo run --bin dioma` открывает окно с живым миром (ягоды
растут, существа едят и умирают), 60 fps на встроенной графике.

### 3.2 Рендер и UI

**Проблема:** графики нет вообще; старая обсерватория удалена из git.

**Цель:** минимальный 2D-рендер в духе оригинала + инспектор существа.

- **Стек:** `eframe 0.35` + `egui` (уже используется в connscope, проверен
  автором; паттерны рейла/дока/инспектора — оттуда).
- **Сцена:** комнаты-Rect с цветом от CA веществ (тепло = красный оттенок,
  влага = синий…); существа — круги с «лицом» (курс, сытость, усталость);
  ягоды — точки с фазой роста.
- **Инспектор существа:** по клику — карточка: глюкоза, голод, усталость,
  повреждения, выученные инстинкты, геном (свёрнуто), «что сейчас хочет».
  Данные — через геттеры `Creature` (уже есть: `hunger`, `glucose`,
  `fatigue`, `wants_food`, `food_eaten`).
- **Оверлей отладки** (за фичей `debug`): спайки, веса, регионы мозга —
  переиспользовать `engine::perf` и опыт connscope.

**Приёмка:** в окне видно комнаты, существа и ягоды; клик по существу
открывает инспектор; FPS-счётчик в статус-баре.

### 3.3 Ввод

**Проблема:** ввода нет.

**Цель (минимум для игры в духе Creatures):**
- ЛКМ по существу — выбрать / «погладить» (→ дофамин, см. 3.8)
- ПКМ — контекстное действие (покормить/дать лекарство — когда появится контент)
- Пробел — пауза; `[`/`]` — скорость симуляции (1×, 2×, 4×, пауза)
- `B` — мозг существа (из прошлого коммита ConnScope: «press B to open a
  creature's brain» — вернуть, это было классно)

Ввод не должен трогать sim напрямую: команды игрока → очередь `PlayerAction`
→ применяются в начале тика. Детерминизм симуляции сохраняется.

### 3.4 Звук

**Проблема:** звука нет (grep по src — пусто).

**Цель:** синтез, не сэмплы (нет ассетов; у автора уже есть «звуковой
словарь» состояний). `rodio` + генерация:
- голод/сытость/боль/радость — по состоянию крови и дофамина;
- события: рождение, смерть, «хрум» (уже есть в скрипте ягоды!);
- фон комнаты — по температуре/влажности (тихий шум, меняющий тембр).

Звук — самая поздняя фаза; интерфейс `AudioBus` (push-события из sim) —
заложить рано, реализовать поздно.

### 3.5 Жизненный цикл существа (главный гэп)

**Проблема:** старения нет (grep age/lifespan/senescence — пусто), сон не
встроен, размножение только в эволюционном бенчмарке.

**Цель — полный цикл в свободном мире:**

```
яйцо → детёныш → взрослый → старый → смерть
        ↑  сон-консолидация каждые N тиков  │
        └────── размножение (спаривание) ───┘
```

- **Возраст:** `Creature.age_ticks`; фазы по порогам. Рост/энергия/обучение
  зависят от фазы (детёныш учится быстрее, старый — медленнее и слабее).
- **Смерть от старости:** накопительный `senescence` (повреждение, растущее
  после пика возраста; урон от голода/болезней ускоряет). Смерть должна быть
  **постепенной и наблюдаемой** (движения медленнее, звуки тише), а не
  мгновенным исчезновением.
- **Сон:** фаза «спит» (не ест, не двигается, уязвим) → по пробуждении
  `memory_snapshot` + `burn_into` (механизм есть!). Усталость (`fatigue`
  уже есть) копит потребность во сне. Ночь/день — через CA света в комнате.
- **Яйца и размножение:** яйцо = агент класса (яйцо, genus-вид родителя)
  со скриптом; вылупление = `spawn_creature` с `spawn_child`-геномом.
  Игрок может подложить/убрать яйцо — это ключевое игровое действие.
- **Размножение:** у существ пол нет — оставить как есть (в оригинале была
  «половая» система; решаем: спаривание = два взрослых рядом при сытости и
  «симпатии» (совместимость генов). Или отложить до фазы 6.)

**Приёмка:** популяция живёт без вмешательства: едят → спят → взрослеют →
размножаются → стареют → умирают; линии вымирают и появляются.

### 3.6 Разум: подключить mind/karmac

**Проблема:** `mind/bridge.rs` (`CreatureMind`, `SpikingBrain`) существует,
но не объявлен в lib.rs — мёртвый код.

**Цель:** подключить мост и дать существам «внутреннюю жизнь»:
- `pub mod mind` в lib.rs (за фичей `karmac` или безусловно — karmac уже
  тянется зависимостями SiMuse).
- CreatureMind поверх рефлекторного мозга: GNW-канал «что сейчас важно»
  (голод/страх/игрушка), который модулирует дофамин и выбор действия.
- **Осторожно:** karmac-арены (hide_seek/platformer) не нужны; берём только
  `brain.rs`/GNW/рабочую память. Не ломать детерминизм: karmac-часть должна
  быть воспроизводимой по сиду (в SiMuse это уже так).

**Приёмка:** у существ появляются наблюдаемые «настроения» в инспекторе
(голодный-злой, сытый-игривый), влияющие на поведение.

### 3.7 Контент-слой: скриптовые агенты

**Проблема:** язык есть, контента нет. В мире два класса: ягода (1/2) и
болванка.

**Цель — каталог агентов (порядок по ценности):**
1. **Ягода** (есть) — доработать: 2-3 вида с разной питательностью/токсичностью
2. **Игрушка** — ACTIVATE1 по клику → дофамин существу рядом (обучение через игру)
3. **Обучающий стенд** — свет/звук → существо учится ассоциации (использовать conditioning-механику)
4. **Дверь-переход** между комнатами (env уже имеет двери как геометрию; нужен агент-проход)
5. **Ловушка/яма** — HIT-слот, урон
6. **Лекарство/яд** — меняет CA комнаты или химию крови существа
7. **Гнездо** — место для яиц, «дом»

Каждый агент = скрипт + спрайт-примитив (круг/квадрат/звёздочка) + класс.
Инвентарь команд скриптовой ВМ расширять по мере надобности (химия крови,
эмоции — через новые команды в `engine_commands()`).

**Приёмка:** 10–20 скриптовых агентов в `resources/agents/`, мир с тремя
комнатами, в котором есть что делать кроме наблюдения.

### 3.8 Обучение игроком (ключевая механика Creatures)

**Проблема:** дофаминовая пластичность есть, канала «похвала/наказание»
от игрока нет.

**Цель:** клик по существу = дофаминовый сигнал в мозг:
- погладить (ЛКМ) → положительный дофамин → подкрепление текущего поведения;
- шлёпнуть (ПКМ по существу) → отрицательный сигнал;
- клик по игрушке рядом → «смотри, это интересно» (веха-стимул).

Реализация: `PlayerAction::Reward(id, ±)` → в `Creature::apply_reward` →
`Brain::apply_dopamine` (механизм уже есть в SiMuse/neurons).

**Приёмка:** существо можно научить за 2-3 минуты «подходить к стенду» и
отучить от поедания ядовитых ягод (отрицательное подкрепление).

### 3.9 Сохранение/загрузка мира

**Проблема:** `.taas` используется только в `sardana_probe` для чтения
внешнего файла. Игру нельзя закрыть.

**Цель:** `world.save(path)` / `world.load(path)`:
- комнаты: CA веществ, двери;
- агенты: класс, позиция, vars, состояние скриптов, очередь сообщений;
- существа: геном + выученные веса/инстинкты (через `taas-format` снапшоты
  мозга — они уже есть в SiMuse: `save_hetero_snapshot` и пр.);
- сид + счётчик тиков (детерминизм продолжения);
- версия формата (как `BioPopulationSnapshot` — отказ от старых версий).

Формат: расширить `.taas` (или `.taas` + JSON-манифест рядом). Снапшоты
био-ВМ (`biovm.rs`) уже имеют version-проверки — взять за образец.

**Приёмка:** play 10 минут → сохранить → перезапустить → загрузить →
состояние бит-в-бит совпадает (детерминированный тест round-trip).

### 3.10 Генетика и селекция для игрока

**Проблема:** геном и мутации есть, но селекция автоматическая.

**Цель:** игровой слой поверх `CreatureGenome`:
- инспектор генома (свёрнутый список генов, «что мутировало у ребёнка»);
- подкладывание яиц / выбор пары;
- «генетическая карта» линии (родословная — граф предков).

Не мешать автоматической эволюции: игрок — селекционер, а не редактор.

### 3.11 Болезни, токсины, лечение

**Проблема:** `tissue`/`cell_chemistry` — заготовки; болезней нет.

**Цель:** минимальный цикл «болезнь → диагноз → лечение»:
- токсины (ядовитые ягоды, гниль) → химия крови отклоняется → симптомы
  (вялость, дрожь, шум в звуке);
- лекарство — агент, меняющий химию;
- «диагностика» игроком через инспектор (уровни веществ).

Это поздняя фаза, но **химия крови уже есть** (`Blood`, стехиометрия) —
интеграция дешёвая.

### 3.12 Производительность и детерминизм

- **Профилирование:** `engine/perf.rs` есть; добавить таймеры по фазам тика
  (world / body / brain / render) в debug-оверлей.
- **GPU:** `engine/gpu.rs` + `pillars-wgpu` в зависимостях — целевой путь для
  больших популяций (сотни существ × HAAP-мозги). Пока — CPU, но считать
  бюджет: 100 существ × 500 подшагов × 10K нейронов — это уже тяжело;
  держать в голове LOD: тонкие подшаги только для ближних/активных.
- **Детерминизм-тесты:** два прогона `Arena` с одним сидом → идентичный
  журнал; golden-файлы для ключевых сценариев (рождение-обучение-сон-смерть).
  Рендер/ввод/звук не должны влиять на sim (иначе тесты ломаются).

## 4. Целевая архитектура (слои)

```
┌────────────────────────────────────────────────────┐
│ ui/        окно, рендер, ввод, инспектор, оверлей  │  (eframe/egui)
├────────────────────────────────────────────────────┤
│ game/      PlayerAction, камера, скорость, пауза,   │
│            аудио-шина (события sim → звук)          │
├────────────────────────────────────────────────────┤
│ sim/       Arena (свободный режим) + жизненный цикл │
│            (возраст/сон/яйца/размножение)           │
├────────────────────────────────────────────────────┤
│ world/     агенты, слоты, скрипты, сообщения        │  ← контент (скрипты)
├────────────────────────────────────────────────────┤
│ mind/      мост в karmac (GNW, настроение)          │  ← подключить!
├────────────────────────────────────────────────────┤
│ creature/  мозг + кровь + геном + обучение игроком  │
├────────────────────────────────────────────────────┤
│ body/ env/ script/                                 │
├────────────────────────────────────────────────────┤
│ engine/    геном, рост, спайки, Пифия, тропика,     │
│            сон-консолидация, био-ВМ                 │
├────────────────────────────────────────────────────┤
│ taas-checkmate (pillars, karmac, prometheus-grow,   │
│                 pillars-connectome, taas-format)    │
└────────────────────────────────────────────────────┘
```

Правила:
- `sim` и ниже **не знают** о ui/game (инверсия: ui читает, game шлёт
  PlayerAction в начало тика);
- новые слои `game/` и `ui/` — единственные, кто может зависеть от egui/winit/rodio;
- весь игровой контент — данные (скрипты + конфиги), не код.

| **2. Жизнь** | возраст, старение, смерть от старости, сон-консолидация в цикле, яйца, размножение | популяция самоподдерживается без вмешательства |
| **3. Разум** | подключить mind/karmac, настроения в инспекторе | у существ видны «характеры», влияющие на поведение |
| **4. Обучение** | клик-дофамин (похвала/шлёп), игрушка-стимул | существо обучается за 2-3 минуты |
| **5. Мир** | 10-20 скриптовых агентов, 3+ комнаты, двери-переходы | в мире есть чем заняться кроме наблюдения |
| **6. Наследие** | save/load мира, инспектор генома, родословная | round-trip бит-в-бит; игру можно закрывать |
| **7. Атмосфера** | звук (синтез), анимации, полировка | звуковой словарь состояний слышен |
| **8. Глубина** | болезни/токсины/лечение, задачи и прогрессия | есть что терять и что лечить |

Порядок важен: 1 без 2 — «аквариум», 2 без 1 — «симуляция без глаз».
Фазы 0–2 — минимальный вертикальный срез «настоящей игры».

## 6. Риски

| Риск | Митигация |
|---|---|
| HAAP-мозги дорогие при сотнях существ | LOD: тонкие подшаги только активным; GPU-путь через pillars-wgpu; бюджет-тест в CI |
| karmac нарушит детерминизм | тесты «два прогона одного сида»; karmac-часть за фичей, по умолчанию выключена до стабилизации |
| Разрастание ui-слоя в god-объект | трейт `Mode` (урок connscope): извлекать при первом новом режиме, не раньше |
| Скриптовый контент без тестов | скрипт-смоук: каждый агент из каталога проходит `compile + 1000 тиков` без ошибок |
| Рефакторинг затянется и убьёт интерес | вертикальный срез (фазы 0–2) — приоритет над полировкой |

## 7. Открытые вопросы

1. **Пол существ** — вводить или оставить бесполое размножение? (Влияет на
   генетику, селекцию и контент фазы 6.)
2. **Смерть** — насколько «жестокий» мир: перманентная смерть линии или
   подстраховка (яйцо-копия)? Оригинал был безжалостен.
3. **Скорость тика в игре** — 25 мс реального времени или «мир тикает
   быстрее» (например, 5 тиков/сек при 60 fps рендера) — влияет на всю
   калибровку метаболизма.
4. **Ночь/день** — нужен ли цикл освещения (CA света уже есть) или комнаты
   живут в вечном «дне»?

Рекомендация авторам: ответить на 1 и 3 **до** фазы 2 — они меняют ядро
жизненного цикла, а не обвязку.
