# Дорожная карта мозга: от LIF-рефлексов к гибридным зонам

Концепт «гибридного мозга»: каждая доля — своя модель динамики и свой режим
обучения. Текущий мозг — LIF + STDP онлайн (работает в игре); будущий — смесь
LIF/Wilson–Cowan/LSTM/ANN/гибрид-лимбики. Этот документ фиксирует стадии,
карту зон и честные ограничения. Визуализация концепта — `engine::viz`
(формат `dioma_brain_viz_v2`), вьюер `examples/brain_viz.rs`, артефакты
`docs/viz/brain_seed42.html` и `docs/viz/brain_zones.html`.

## Стадии

| Стадия | Состав | Динамика | Обучение | Статус |
|--------|--------|----------|----------|--------|
| A — текущее ядро | avoidance: SL/SR/WL/WR/I/ML/MR (120 нейронов) | LIF (движковый `Brain`) | STDP + дофамин, онлайн | ✅ в игре |
| B — транш 3: зрение | + VL/VR (30×2), ASSOC_E (90)/ASSOC_I (30) = 300 | LIF | STDP онлайн + инъекции | 🎨 концепт (viz) |
| C — зоны | + CORTEX, PLAN (WC), MEM (LSTM), DRIVES/MOOD, AMYG, SOCIAL, SEQ (21 регион, ~1245 нейронов) | гибрид: lif/wc/lstm/ann/hybrid | смешанное (см. карту) | 🎨 чистый дизайн (viz) |
| D — интеграция | мост pillars-раннер → игровые существа | гибрид | смешанное | 🔧 требует работы |

Предусловия:

- **A**: нет (база).
- **B**: сенсорные токи VL/VR (глаз-бины); инъекции в ASSOC (прецедент
  `reward_now_gated` / `schedule_reward`); рост будущей схемы — длинная
  диагональ WL→MR/WR→ML (240 мкм) замыкается не на всех сидах (сид 42 не даёт).
- **C**: ядра WC/LSTM/ANN + офлайн-обучение + запекание весов в геном
  (замечание (a)); производительность (замечание (b)); связка «зоны → регионы».
- **D**: HeteroRunner для существ (единый тик), офлайн-тренировка памяти,
  при необходимости GPU (pillars-wgpu).

## Карта зон (стадия C)

| Зона | Регионы (нейроны) | Модель | Обучение |
|------|-------------------|--------|----------|
| Ядро | SL/SR/WL/WR/I/ML/MR (120) | LIF | STDP + дофамин, онлайн — уже работает |
| Зрение | VL/VR (60×2) | ANN-энкодер | градиент офлайн → веса в геноме (сейчас — сырые бины) |
| Ассоциативный хаб | CORTEX_E (400) / CORTEX_I (120) | LIF + инъекции | STDP онлайн + внешние токи |
| Планирование | PLAN_E (80) / PLAN_I (40) | Wilson–Cowan | параметры из генома |
| Гиппокамп | MEM_CTX (100) / MEM_OUT (30) | GRU/LSTM | градиент офлайн → веса в геноме |
| Лимбика | DRIVES (40) / MOOD (30) | гибрид (кровь → тоны + модуляция) | регуляторный геном |
| Оценка | AMYG (50) | LIF | STDP онлайн (вторичное подкрепление) |
| Социальная | SOCIAL (40) | LIF | STDP онлайн |
| Премотор | SEQ_E (50) / SEQ_I (25) | Wilson–Cowan | параметры из генома |

Итого 1245 нейронов (сумма фиксированных размеров; «~1400» в ТЗ — ориентир,
ядро взято из `avoidance_layout()`). Инъекции в ассоциативный хаб —
внешние токи состояния/награды из других модулей.

## Честные замечания

### (a) LIF онлайн vs офлайн-baked градиент (GRU/LSTM/ANN)

LIF-зоны учатся онлайн STDP+дофамин: локально, дёшево, без глобального
состояния — подходит рефлексам и ассоциациям. GRU/LSTM/ANN обучаются
градиентом ОФЛАЙН (BPTT), потому что:

- детерминизм: веса после обучения ЗАПЕКАЮТСЯ в геном (прецедент
  `save_baked`) — симуляция повторяема между запусками, как с baked-инстинктами;
- BPTT в реальном времени нестабилен и дорог; офлайн-сессия + фиксация
  укладывается в существующий конвейер «родитель → геном → ребёнок».

Смешение: обученные зоны (память, зрение) — константы в тике, пластичность
живёт только в LIF-долях; лимбика модулирует пластичность per-region
(регуляторный геном), но не переписывает baked-веса.

### (b) Производительность

Замер: ~0.15–0.24 мс/существо/тик при 120 нейронах (LIF, текущее ядро).
Стадия C — ~1245 нейронов, ×10 → прогноз ~1.5–2.4 мс/существо/тик на CPU
(связи растут сверхлинейно — реалистичнее верхняя граница). Сто существ →
150–240 мс/тик — превышает бюджет кадра. Вывод: rayon-параллелизм по
существам или GPU-путь (pillars-wgpu) нужны ДО внедрения стадии C, а не после.

### (c) Доступность ядер (разведка по crates/SiMuse, SiMuse НЕ изменён)

Готово как API-ядро (crates/pillars): `step_lif` / `step_lif_at`, `step_wc`
(Wilson–Cowan), `step_izhikevich` (+dual), `step_fhn`, `step_haap`, `step_hr`,
`step_adex`, `step_saw`, `step_gco`, `step_neuromotor`, eprop
(LIF/Izh/AdEx/Saw), bcm, stdp_update.

Смешанный раннер ЕСТЬ: `pillars-connectome::hetero` (`HeteroRunner`,
`GroupEngine`: Alpha / HhStub (удалён) / Haap / Izh / Rate / Transformer) —
группы нейронов РАЗНЫХ моделей на одном CSR-коннектоме с общей очередью
спайков (гетерогенный мозг уже исполним в pillars-коннектоме).

Честно, чего нет:

1. в hetero НЕТ групп Wilson–Cowan и LSTM/GRU: `step_wc` — только API-функция
   (не подключена в раннер), ближайшее к памяти — SurgeN-трансформер;
2. ANN-энкодера зрения нет нигде;
3. hetero НЕ подключён к игровым существам dioma: мозг существа — собственный
   `engine::neurons::Brain` (LIF+STDP); pillars-connectome используется только
   в теле (`body/organs.rs`: spine/midbrain `BrainRunner`) и GPU-пути.

→ Мост «pillars-раннер ↔ существа» предстоит собрать (стадия D): общий тик,
масштабы токов, запекание весов.

## Прецедент концепта

`kailo\docs\DNA.md` §2.2 — ген модели на регион (байт 1+r →
`BrainModel::ALL[b % 23]`, 23 модели pillars: Lif…Wc…Triangulated): «каждый
регион может быть своим типом нейрона — вся мощь гетерогенного мозга». Наш
концепт зон — то же на уровне долей (зона = группа регионов одной модели),
с явным режимом обучения и инъекциями между модулями.

## Пайплайн обучения (python-бинды)

Зоны с baked-градиентом (зрение ANN, память GRU/LSTM) учатся ОФЛАЙН вне
игры, а в игру попадают только запечённые веса. Три фазы:

### Фаза 0 — обмен файлами `.dbw` (сделано)

- **Формат**: DBW1 (Dioma Baked Weights, v1) — бинарная укладка LE,
  документирована и реализована в `crates/dioma-engine/src/engine/baked.rs`
  (загрузчик `BakedTensors` + инференс `BakedMlp`/`BakedGru`); серверная
  сериализация — тот же модуль, детерминированная.
- **Экспортёр**: `tools/export_dbw.py` — обучение маленькой сети на чистом
  Python (XOR 2→8→1, ручной backprop, сид фиксирован; numpy — опциональное
  ускорение арифметики) + экспорт в DBW1; режим `--torch-gru` для GRU-памяти.
- **Формат-контракт**: golden-байты структуры сверены тестами Rust
  (`golden_prefix_bytes`) и `--selftest` Python — обе стороны укладывают
  один и тот же поток байт.
- **Пример**: `python tools/export_dbw.py --out %TEMP%\xor.dbw` → игра читает
  файл, `BakedMlp::forward` выдаёт 4 точки XOR ≈ 0/1 (кросс-валидация
  прогонялась временным примером, цифры в отчёте транша).

### Фаза 1 — pyo3-бинды движка

- Импорт `dioma_engine` из Python через pyo3; RL-петля с `Arena::step`
  (`sim/mod.rs`) для офлайн-выращивания: python-тренер дёргает арену,
  собирает траектории, считает градиенты и возвращает веса в игру.
- Детерминизм сохраняется: сиды арены фиксированы, веса запекаются после
  каждой сессии (прецедент `save_baked`).

### Фаза 2 — батч-GPU обучение

- Большие транши (зрение-энкодер, гиппокамп) считаются батчами на GPU
  (numpy/torch уже умеют), результат — тот же `.dbw`, формат не меняется.
- Игра остаётся чисто CPU-инференсом: GPU нужен только офлайн-тренеру.

### Правила детерминизма

1. веса всегда ЗАПЕКАЮТСЯ в файл/геном — в игре нет «живого» обучения
   baked-зон;
2. сиды фиксированы: `random.seed(seed)` / `torch.manual_seed(seed)` в
   тренере, `XorShift(seed)` в арене;
3. в игре НИКОГДА не исполняется бэкпроп-код: `BakedMlp`/`BakedGru` — только
   forward, ошибки формата падают на загрузке, а не в тике.

### Связь с зонами концепта

- **VIS(ann)** (зрение, стадия C): ANN-энкодер «картинка → вектор признаков →
  токи» — BakedMlp на тензорах `layer{i}.w/b`, обучение фазой 0/2;
- **MEM(lstm)** (гиппокамп): GRU/LSTM-память — BakedGru на тензорах
  `gru.wz/wr/wh, gru.uz/ur/uh, gru.bz/br/bh`, обучение офлайн (фаза 1),
  батч-GPU (фаза 2);
- стадия B (транш 3): регионы VL/VR/ASSOC_E/ASSOC_I уже в схеме
  `grow::stage_b_layout` (единый источник правды для `viz`), зрение
  помечено `planned` — переключение популяции отдельным траншем.

## Шептун: прототип (этап 0 пайплайна)

Первый РЕАЛЬНЫЙ прогон baked-пайплайна на данных движка: GRU учится
ПРЕДСКАЗЫВАТЬ действия спайкового мозга существ по их сенсорам
(мировая модель мозга; владелец: «обучить шептуна LSTM на нескольких
особях, чтобы LSTM понял как работать с их мозгами»).

- **Данные**: `tools/whisperer_data.json` — 8 особей × 2000 тиков, сэмпл =
  12 входов (обоняние/зрение/стены/еда у рта/хочу есть/голод/глюкоза/
  усталость/курс) + реконструированное действие (steer/drive/eat).
  Рекордер `crates/dioma-engine/examples/whisperer_data.rs`; сенсоры —
  через новый наблюдательный мост `Arena::last_sense` (аддитивное поле,
  поведение движка не тронуто). 6 особей train (сиды 1000..1005),
  2 hold-out (1006, 1007).
- **Модель**: `tools/train_whisperer.py` — GRU 12→32→3 (steer=tanh,
  drive=σ, eat=σ), ручной numpy BPTT (T=16), Adam, 30 эпох, сид 123.
- **Метрики** (python и rust совпадают до 4 знака; отчёт
  `tools/whisperer_report.txt`):
  - train: r(steer)=+0.66, r(drive)=+0.85, eat_acc=0.991;
  - hold-out: r(steer)=+0.008 (c1007: +0.87 — обобщил, c1006: −0.85 —
    зеркально инвертировал), r(drive)=+0.89, eat_acc=0.996.
  - Вывод: GRU поймал ДРАЙВ (кровь/мотивация предсказуемы) и руль ЗНАКОМЫХ
    мозгов; руль незнакомых мозгов обобщается частично (хаотичный спайковый
    steering). Что поможет: спайк-входы вместо сенсоров, больше особей,
    per-brain readout.
- **Паритет**: `crates/dioma-engine/examples/whisperer_check.rs` —
  python(f64)↔rust(f32) на 5 золотых окнах: max|Δ|=2.7e-7 ≤ 1e-4.
- **Артефакты**: `tools/whisperer.dbw` (~18 КБ, 11 тензоров: gru.* +
  layer0.*), `tools/whisperer_golden.json`.

Как перезапустить (dioma-engine — отдельный пакет, не член воркспейса:
команды cargo — из `crates/dioma-engine`, пути к tools — `../../tools/…`):

```text
# 1) запись датасета
cd crates/dioma-engine
cargo run --release --example whisperer_data -- --creatures 8 --ticks 2000 --out ../../tools/whisperer_data.json --seed0 1000
# 2) обучение + запекание весов (numpy; сид 123 — детерминированно)
python ../../tools/train_whisperer.py --data ../../tools/whisperer_data.json --epochs 30
# 3) паритет python↔rust + качество на hold-out
cargo run --release --example whisperer_check -- --data ../../tools/whisperer_data.json --dbw ../../tools/whisperer.dbw --golden ../../tools/whisperer_golden.json
```

## Глаза: прототип ANN-энкодера ретины (этап 0 пайплайна, дистилляция)

Сегодня vis_l/vis_r считает геометрия в `Arena::sense`. Глаза будущего —
энкодер «сырая сетчатка → сигналы»: ретина (16 лучей по конусу ±75°,
канал = ягодность/стенность/соседность) богаче бинов, ANN сжимает её в
полезный вектор. ПРОТОТИП учится дистилляцией: цель = аналитические
сигналы глаза (vis_l/vis_r/wall_ahead из `Arena::last_sense` + пеленг/
дистанция на ближайшую съедобную ягоду в поле зрения). Потом (Стадия C)
ретина заменит бины, а запечённые глаза встанут как энкодер перед VL/VR.

- **Данные**: `tools/eye_data.json` — 8 особей × 1500 тиков, сэмпл =
  ретина 48 f32 (16 лучей × [ягодность, стенность, соседность]) + 6 целей.
  Рекордер `crates/dioma-engine/examples/eye_data.rs`; 6 особей train
  (сиды 2000..2005), 2 hold-out (2006, 2007). Отклонения от «голой» спеки
  (в шапке рекордера): стены непрозрачны и для ретины (иначе цель
  vis_l/vis_r не выводима); 2-й «статичный» криттер-наблюдатель (якорь +
  возврат позиции каждый тик) — чтобы канал соседности был живым;
  спящий криттер = «глаза закрыты» (ретина и цели нулевые). Случайный мозг
  спит ~75% тиков — это настоящая дистрибуция, а не шум.
- **Модель**: `tools/train_eye.py` — MLP 48→24 (tanh)→6 (линейный), MSE,
  Adam (lr 0.01, батч 128), 40 эпох, сид 123. Экспорт DBW1
  (`layer0.w/b`, `layer1.w/b`) → `BakedMlp`.
- **Метрики** (rust совпадает с python до 4 знака; отчёт
  `tools/eye_report.txt`), hold-out, все сэмплы / «бодрые»:
  - vis_l: r=+0.993 / +0.983, vis_r: r=+0.992 / +0.980 — ОРИЕНТИР ТЗ
    (r>0.9) взят;
  - food_bearing_cos r=+0.945 / +0.740, food_dist_norm r=+0.945 / +0.574,
    wall_ahead r=+0.967 / +0.881;
  - food_bearing_sin r=+0.572 / +0.556 — слабее всех: sin антисимметричен
    (знак = лево/право, нуль на курсе), бины грубые (11.25°) — сеть
    смазывает знак пеленга на незнакомых особях.
- **Паритет**: `crates/dioma-engine/examples/eye_check.rs` — 5 золотых
  сэмплов (seed 123, ненулевая ретина): max|Δ|=3.4e-7 ≤ 1e-4.
- **Артефакты**: `tools/eye.dbw` (5382 байта, 4 тензора, 1326 весов),
  `tools/eye_golden.json`.

Как перезапустить (из корня репозитория; engine — отдельный пакет, не член
воркспейса — команды cargo через `--manifest-path`):

```text
# 1) запись датасета
cargo run --manifest-path crates/dioma-engine/Cargo.toml --release --example eye_data -- --creatures 8 --ticks 1500 --seed0 2000 --out tools/eye_data.json
# 2) обучение + запекание весов (numpy; сид 123 — детерминированно)
python tools/train_eye.py --data tools/eye_data.json --epochs 40
# 3) паритет python↔rust + качество на hold-out
cargo run --manifest-path crates/dioma-engine/Cargo.toml --release --example eye_check -- --data tools/eye_data.json --dbw tools/eye.dbw --golden tools/eye_golden.json
```

## Эмерджентность: закрытый контур

Наблюдательное исследование: что РЕАЛЬНО возникает в естественном прогоне,
без скриптовых циклов голода и тестовых подпорок. Раннер
`crates/dioma-engine/examples/emergence_run.rs` гоняет два сценария —
«Дикий лес» (6 существ сиды 3001..3006, 10 ягод, 30000 тиков, голод нарастает
сам из дефолтной крови; метрики по третям: food_rate, сон, занятость 8×8,
NN-дистанции, «личности» F-ratio, прокси «следования») и «Поколения»
(Evolution, сид 42, 5 поколений, история + дельты Болдуина) — и пишет
`tools/emergence_data.json`; `tools/emergence_report.py` рисует
самодостаточный `tools/emergence_report.html` (canvas-графики, тёмная тема)
с автоматическими вердиктами «ЕСТЬ / СЛЕДЫ / НЕТ» и «честными оговорками».

Главный честный результат (сид 777): закрытый контур на еде НЕ замыкается —
новорождённые с дефолтной кровью не голодают (сон-петля: +15 глюкозы за сон
держит её над порогом дефицита 150, HUNGER не синтезируется), а единственный
сид, у которого голод возникает естественно, не умеет охотиться (навык
требует дофамина от первой еды — замкнутый круг). Движок во всех охотничьих
сценариях сам впрыскивает стартовый голод (эволюция — `NEWBORN_HUNGER`),
поэтому «естественная» охота — точка роста, а не текущее поведение. При этом
STDP учит стены: у всех существ к концу прогона есть выученные рефлексы
избегания (дофамин до 8.0). Эволюция показывает классический Болдуин:
инстинкт-ген фиксируется у 100% популяции за 1–2 поколения (дофамин 8/8),
но средняя добыча НЕ растёт (7.1 → 5.3 порц/поколение) — «ловушка фиксации».

Как перезапустить (из корня репозитория; engine — отдельный пакет, не член
воркспейса — команды cargo через `--manifest-path`):

```text
# 1) полный прогон: «Дикий лес» 30000 тиков + «Поколения» 5 поколений
cargo run --manifest-path crates/dioma-engine/Cargo.toml --release --example emergence_run -- --out tools/emergence_data.json
# 2) отчёт (самодостаточный HTML, canvas-графики, вердикты)
python tools/emergence_report.py --data tools/emergence_data.json --out tools/emergence_report.html
# смоук пайплайна (3000 тиков + 2 поколения, вердикты помечаются «СМОУК»):
#   ... emergence_run -- --out tools/emergence_data.json --quick
```

### Замыкание контура (ребаланс метаболизма, 2026-08-28)

Итог: закрытый контур на еде ЗАМКНУЛСЯ — те же условия (сид 777, сиды 3001–3006,
10 ягод, 30000 тиков), те же метрики. Три рычага:

1. **Сон не кормит** (`body/metabolism.rs`): `Blood::sleep()` капает глюкозу на
   `SLEEP_GLUCOSE_CAP=120` (< порога дефицита 150). Раньше +15 к потолку 255
   держали глюкозу 252–255, HUNGER не синтезировался вовсе.
2. **Новорождённый арены голоден** (`sim/mod.rs`): `Arena::spawn_creature`
   ставит `ARENA_NEWBORN_HUNGER=120` (> порога wants_food 40) — тот же паттерн,
   что `NEWBORN_HUNGER=200` эволюции. Эволюция перезаписывает 120 своим 200
   сразу после спавна — применяется одно значение, двойного накопления нет.
3. **Экономика глюкоза↔голод ребалансирована** (`body/metabolism.rs`):
   эмиттер `GLUCOSE_DEFICIT→HUNGER` 0.012 → 0.08. Это оказалось НЕОБХОДИМО:
   при одной только капе сна равновесие HUNGER при глюкозе 120 — ≈12 (синтез
   0.012×30 = 0.36/тик в 6 раз слабее ферментативного утоления 0.02×120 =
   2.4/тик) — голод не доходил до wants_food (40): «поел раз — сыт навсегда».
   0.08 даёт равновесие ≈80 (> 40, ниже паники 240): голод устойчиво
   синтезируется, охота не умирает.

Честные числа (см. `tools/emergence_report.html`, вердикты генератора):
