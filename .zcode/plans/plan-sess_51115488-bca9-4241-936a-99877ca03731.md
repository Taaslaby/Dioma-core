# Каркас UI-движка на спрайтах dioma-render (TTF-текст, базовые виджеты)

## Цель
Модуль `ui` внутри dioma-render: собственный immediate-mode UI (панели/кнопки/текст/бары) поверх сцены, без egui — рендерится существующим спрайтовым пайплайном. Текст — настоящий TTF с кириллицей через fontdue, растеризуется в общий атлас при запуске. egui остаётся для дебага, не трогаем.

## Архитектура
```
src/ui/
├── mod.rs        — UiSystem (ресурсы + immediate-фрейм), UiInput, Response
├── layout.rs     — Rect (экранные px, Y вниз), Anchor (углы/центр), helper'ы
├── nine_patch.rs — генерация скруглённой панели + 9 спрайтов (углы/кромки/центр)
├── text.rs       — UiFont: fontdue → RGBA-глифы → атлас (add_rgba), layout строки
└── widgets.rs    — Panel, Label, Button, ProgressBar
```

## Ключевые решения
1. **Рендер**: UI-виджеты и глифы — обычные `Sprite` (layers 1000+) в отдельном `SpriteBatch`; один проход поверх сцены с identity-камерой (`Camera::new(viewport)`, отдельный uniform-буфер — паттерн `render_debug_overlay`) и `LoadOp::Load`. Глифы кладём в общий атлас через `add_rgba` → один батч, одна текстура, один draw call на fx-группу.
2. **Текст**: зависимость `fontdue = "0.9"` (чистый Rust). Шрифт — OFL с кириллицей (PT Sans, ~130KB), файл `crates/dioma-render/assets/fonts/PTSans-Regular.ttf` + LICENSE, `include_bytes!`. Растеризация базового набора (ASCII + А-я, Ёё + пунктуация) при `UiFont::new`, недостающие глифы — лениво. Один базовый размер (32px глиф, масштаб стилями ×0.5/×0.75/×1).
3. **Панель**: одна процедурная текстура 48×48 (скругление, рамка, полупрозрачный fill) → nine-patch (margins 12px): 9 спрайтов с под-UV; края тянутся, углы нет.
4. **Button**: панель + label; состояния: обычный/hover (tint ярче + `SpriteFx::Outline`)/pressed (tint темнее). Interaction: id = hash(путь виджетов), состояние hover/click по `UiInput`.
5. **ProgressBar**: два спрайта — подложка + fill (ширина = inner×progress), цифры по желанию.
6. **API (immediate, egui-подобный, упрощённый)**:
```rust
let mut ui = ui_sys.begin(UiInput { cursor, mouse_down, just_pressed });
ui.panel(Anchor::TopLeft, [280.0, 220.0], |p| {
    p.label("Существо #7")?;
    if p.button("Пауза")?.clicked { paused = !paused; }
    p.progress_bar("голод", 0.42);
});
ui.upload(queue);                       // батч
renderer.render_ui(&mut encoder, view, &ui);  // Load-проход, identity-камера
```
Вертикальный стек внутри панели автоматом; якорное позиционирование панели — по углам экрана.

## Этапы
1. `Cargo.toml`: fontdue; скачать PT Sans (OFL) + лицензия.
2. `layout.rs` + `nine_patch.rs` (+ юнит-тесты математик).
3. `text.rs`: шейпинг/кэш глифов + тесты ширины.
4. `widgets.rs` + `mod.rs`: UiSystem/UiFrame/Response, upload.
5. `Renderer::render_ui` (по образцу render_debug_overlay: identity-камера, Load, scissor не нужен).
6. Тесты: юнит (layout/nine-patch/текст/id-стабильность) + headless `tests/ui_offscreen.rs` (панель с текстом и кнопкой рисуются, пиксельные проверки в духе существующих) + example `examples/hud.rs` со смоуком `--frames=60`.
7. Проверка: cargo test в dioma-render, смоук hud, сборка game.

## Не делаем (сознательно)
- Скролл/клиппинг контента, слайдеры/чекбоксы, drag&drop, анимации переходов — следующий транш.
- egui в game.rs не трогаем; переключение HUD игры на новый UI — отдельный заход.
- Мультилайн-вёрстка (перенос слов) — простой перенос по \n.

## Риски
- Шрифт: если скачать PT Sans не выйдет — беру другой OFL с кириллицей (Noto Sans/Ubuntu), API не меняется.
- Масштабирование глифов между дискретными размерами даёт лёгкое размытие — лечится добавлением размеров по мере надобности.
